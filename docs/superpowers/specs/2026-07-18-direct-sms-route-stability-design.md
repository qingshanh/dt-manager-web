# Direct SMS 路由稳定性与正式部署隔离设计

**日期：** 2026-07-18
**状态：** 已确认，待实施
**范围：** 直连短信监听、目标号码解析、正式部署的模拟器隔离、运行时重连与诊断写入

## 1. 背景与证据

当前直连监听可以在模拟器 App 停止时接收普通短信，已经通过不同账户、不同国家号码的交叉测试验证。部分外部验证码在项目和官方客户端中都没有出现，因此这类事件属于发送方或号码供应商的上游投递问题，不能通过修改项目解析器解决。

项目本身同时存在以下可复现缺陷：

1. 辅助认证 link 通常在 3 至 7 秒内结束，当前代码会立即释放已经注册的短信路由。主备 worker 随后反复争抢 `updateClientLink` 路由。
2. 每次辅助 link 重建都会重新发送启动离线补拉，导致 `offlineCatchupSends` 持续增长。
3. 多账户在代理或上游连接失败时以最多 1 秒的退避同时重连，放大 TLS、socket、Prisma 写入和日志压力。
4. Windows 后端曾在高频重连期间以 `0xC0000409` 异常退出。现有证据能证明资源风暴与崩溃高度相关，但不足以断言单一原生库根因。
5. 短信二进制元数据包含发送方、真实接收号码和附加数字标识。当前解析器扫描所有数字串并按长度和字典序选择，可能把附加标识误认为接收号码。
6. `direct_monitor_app_catchup_enabled` 默认开启，并在后端启动时把用户设置的 `false` 重写为 `true`，违反正式部署必须脱离模拟器的要求。

## 2. 目标

- 辅助 link 短暂重连不得改变已经生效的短信路由所有权。
- 只有 push worker 明确失败、主节点明确不可用、监听停止或宽限期超时后才允许备用网关接管。
- 启动离线补拉在一个监听生命周期内有账户级限流，不因 link 重建重复发送。
- 代理或网关故障时连接尝试有指数退避、随机抖动和共享熔断，恢复后分批重连。
- 高频监听诊断写入串行合并，数据库最多一个写入进行中，并最终保存最新快照。
- 目标号码优先按已确认的二进制 envelope 结构解析；不再依靠数字串排序猜测。
- 正式直连默认关闭 App、helper 和 ADB 补拉；模拟器只能作为显式启用的测试能力。
- 不记录或提交真实手机号、邮箱、token、设备标识、局域网地址或原始敏感抓包。

## 3. 非目标

- 不整体恢复 `566c195` 的全部 WIP 修改。
- 不回退当前 epoch/reservation 并发保护。
- 不承诺修复官方客户端也未收到的供应商或验证码平台上游投递问题。
- 不让 Docker、Linux systemd 或普通生产部署依赖 ADB、模拟器或桌面 App。
- 不在本次修复中重构整个 `direct-gateway.ts` 协议层。

## 4. 路由所有权设计

### 4.1 所有权与传输连接解耦

路由所有权属于“账户监听生命周期”，辅助认证 link 只是用于注册和维护该路由的可替换传输。关闭辅助 link 时：

- 关闭 socket、清除 link 引用和 link 级 trace。
- 保留 `linkRegistrationEpoch` 对应的 route owner。
- 下一条认证 link 建立后，若当前 host 仍持有相同 epoch，则不重新 claim，也不重复注册。

路由只在以下条件释放：

- 对应 push worker 整体退出。
- 监听被停止或被新的监听实例 preempt。
- 当前 owner 的 push socket 明确失败并超过 owner grace。
- 主 owner 注册失败并调用 `markPrimaryUnavailable()`，备用 worker 获得接管资格。

旧 epoch 的迟到 release 必须不能释放新 owner。

### 4.2 Owner grace

辅助 link 短断进入宽限期，不立即将 owner 置空。宽限期内：

- 当前 owner host 优先重建认证 link。
- 备用 host 保持认证或 push 读取，但不能覆盖路由。
- 只有 owner push 路径也不可用或宽限期到期，才释放 epoch 并允许备用 claim。

默认宽限期应覆盖已观测到的 3 至 7 秒 link 波动，初始值采用 15 秒，并作为内部常量，不新增用户设置。

## 5. 认证 link 与心跳时序

认证 link 使用以下顺序：

1. `openPrelogin(account)`。
2. `bootstrapAuthenticatedSession(...)` 完成认证启动。
3. 在 bootstrap 已发送认证请求后执行必要的 prime 请求。
4. 注册短信路由。
5. 执行 private-number 等较大维护请求。
6. 认证完成后才启动 5 秒 paired keepalive。
7. 进入 ready 阶段并开始读取 push。

bootstrap 前不调用会立即写入的 `startSocketKeepalive()`。socket 错误只记录生命周期阶段、host、持续时间和计数，不记录账户凭据或号码。

## 6. 离线补拉与重连控制

### 6.1 离线补拉

启动离线补拉状态提升到 listener/account 生命周期：

- 路由首次成功注册后发送一次 `requestAllOfflineMessage`。
- 辅助 link 重建不重置发送状态。
- notify-only 和周期补拉继续使用独立节流时间戳。
- 发送失败允许按受控间隔重试，不能在每次 socket 重建时立即重试。

### 6.2 重连退避与共享熔断

每个 host 使用指数退避和 jitter，建议序列为 500ms、1s、2s、4s、8s、最高 30s；成功稳定运行后重置失败计数。

同一个代理地址或直连 transport 共享熔断状态：

- 短时间内连续连接失败达到阈值后进入 open 状态。
- open 状态只允许少量探测连接，其他账户等待。
- 探测成功后进入 half-open，并用 jitter 分批恢复账户监听。
- 熔断等待必须可被监听停止信号中断，不能留下 timer 或 waiter。

## 7. 诊断写入合并

每个 monitor session 使用一个 coalescing writer：

- 同一时间最多一个 Prisma update 在执行。
- 新状态到达时覆盖 pending 快照，不为每个事件排队。
- 当前写入完成后，如果存在更新快照，仅再写一次最新值。
- stop/finalize 时 flush 最终状态。
- writer 失败只记录脱敏错误，不中断短信读取。

该 writer 只负责高频 `routeAddress` 和监听状态诊断，不改变短信消息入库的持久化语义。

## 8. 目标号码解析

已确认的二进制 envelope 在固定头部之后包含两个连续的 LE32 长度前缀数字字段：第一个是发送方，第二个是真实接收号码。附加数字标识可能稍后出现在 `info` 中。

解析策略：

1. Base64 解码 `info` 与 `k3`。
2. 从已确认的 envelope 起始位置读取两个连续的 LE32 长度前缀字段。
3. 校验字段长度、数字字符和缓冲区边界。
4. 第二字段作为候选接收号码；`info` 与 `k3` 一致时优先采用。
5. 结构解析失败时，只接受 `target=`、`recipient=`、`to=` 等显式标签。
6. 无可靠候选时返回 `null`，交给消息运行时依据当前账户已拥有号码进行唯一匹配。
7. 删除扫描全部数字串后按长度和字典序猜测目标号码的兜底。

解析器测试必须使用虚构号码，覆盖“真实接收号码与附加标识长度相同”的回归场景。

## 9. 正式部署与模拟器隔离

- `direct_monitor_app_catchup_enabled` 默认值改为 `false`。
- 删除把 `false` 自动迁移为 `true` 的 legacy rewrite。
- `account-monitor.ts` 在设置缺失或读取失败时也默认 `false`。
- 本地逆向测试可手动设置为 `true`，但后端重启不得覆盖用户选择。
- Docker、Linux 普通部署和本地正式直连在没有 ADB 的情况下行为一致。

## 10. 测试与验收

### 自动测试

- sticky route 在辅助 link 抖动时保持 owner，备用不能抢占。
- owner push 明确失败或 grace 超时后才允许备用接管。
- 认证和 prime 完成前没有 paired keepalive write。
- 三次辅助 link 重建只发送一次启动离线补拉。
- 多账户代理故障时总连接次数受共享熔断上限约束。
- 100 次诊断更新最多一个写入并发，最终值为最新快照。
- 二进制解析器选择第二个长度前缀号码，不选择尾部附加标识。
- App/ADB fallback 缺省关闭，显式开启仍可用于本地测试。

### 构建与回归

- 后端定向测试和完整测试通过。
- 后端 TypeScript 生产构建通过。
- 前端生产构建通过。
- 已知有效账户的 direct regression 通过。
- 工作树 diff 检查和敏感信息扫描通过。

### 运行时验收

- Windows 连续运行至少 30 分钟，后端子进程不重启。
- route claim/release、`offlineCatchupSends`、连接尝试不持续线性增长。
- CPU、内存、句柄和 TCP 连接数在故障恢复后进入稳定区间。
- 模拟器 App 完全停止后，至少三个已知有效国家号码的普通短信在 10 秒内入库。
- 正确保存短信目标号码。
- 外部验证码使用“项目 + 官方客户端”双通道验证，并与项目监听缺陷分开记录。
